# Entidad: B100 — Balance mensual por subcuenta

Entidad dedicada a B100. Una fila por subcuenta y mes: el dinero de cada subcuenta B100 en cada mes, junto con el dinero y porcentaje reservados para Hacienda.

## Datos que guarda

Todos los campos son `NOT NULL` salvo los de auditoría.

| Campo | Tipo | Descripción |
|---|---|---|
| `id` | VARCHAR(50) PK | Clave natural `{tipo}-{AAAA-MM}` |
| `tipo_subcuenta` | ENUM (`save`, `health`) | Tipo de subcuenta B100 |
| `mes` | VARCHAR(7) | Fecha mes-año en **una sola columna** (formato `YYYY-MM`, p. ej. `2026-01`) |
| `balance_mensual` | NUMERIC(12,2) | Dinero de esa subcuenta en el mes |
| `dinero_hacienda` | NUMERIC(12,2) | Dinero apartado para Hacienda |
| `dinero_total_repartir` | NUMERIC(12,2) | Dinero total que reparte B100 al 100% |
| `porcentaje_hacienda` | NUMERIC(5,2) | Porcentaje que se lleva Hacienda (entero, p. ej. 19.00; se divide entre 100 para operar) |
| `pagado_hacienda` | BOOLEAN | Si ya se ha pagado a Hacienda |
| `fecha_creacion` / `fecha_actualizacion` | TIMESTAMP | Auditoría |

## Identificador

Fila única por `(tipo_subcuenta, mes)` ⇒ **clave natural legible `{tipo}-{AAAA-MM}`** (p. ej. `save-2026-07`, `health-2026-07`).

- Resta leer en logs y URLs (`/b100-balances/save-2026-07`).
- Inmutable por construcción (deriva de campos que no cambian).
- Compatible con la convención `VARCHAR(50)` del proyecto.
- Se refuerza con `UNIQUE(tipo_subcuenta, mes)` como red de seguridad.

**Decidido:** identificador natural `{tipo}-{AAAA-MM}`.

## Esquema de la tabla

```sql
CREATE TABLE b100_balances (
  id                   VARCHAR(50)   PRIMARY KEY,
  tipo_subcuenta       VARCHAR(20)   NOT NULL CHECK (tipo_subcuenta IN ('save', 'health')),
  mes                  VARCHAR(7)    NOT NULL,
  balance_mensual      NUMERIC(12,2) NOT NULL,
  dinero_hacienda      NUMERIC(12,2) NOT NULL DEFAULT 0,
  dinero_total_repartir NUMERIC(12,2) NOT NULL,
  porcentaje_hacienda  NUMERIC(5,2)  NOT NULL DEFAULT 19.00,
  pagado_hacienda      BOOLEAN       NOT NULL DEFAULT FALSE,
  fecha_creacion       TIMESTAMP     DEFAULT NOW(),
  fecha_actualizacion  TIMESTAMP     DEFAULT NOW(),
  UNIQUE(tipo_subcuenta, mes)
);

CREATE INDEX idx_b100_balances_mes ON b100_balances(mes);
```

## Endpoints

### Guardar datos de una subcuenta (POST)

Un único endpoint para guardar el balance de una subcuenta en un mes. El front lo llama **una vez por subcuenta** (`POST` para `save` y otro `POST` para `health`).

| Método | Path | Body | Uso |
|---|---|---|---|
| POST | `/b100-balances` | `B100BalanceRequest` (tipo_subcuenta, mes, balance_mensual, dinero_hacienda, dinero_total_repartir, porcentaje_hacienda, pagado_hacienda) | Crear o actualizar el balance de una subcuenta en un mes (upsert por `(tipo_subcuenta, mes)`) |

### Listar balances (GET, paginado)

Obtener la lista de balances de una subcuenta, ordenada y con un número máximo de registros (estilo paginado por límite/orden).

| Método | Path | Query params | Uso |
|---|---|---|---|
| GET | `/b100-balances` | `tipo_subcuenta` (obligatorio), `limit` (nº registros, opcional con default), `order` (`asc`/`desc` por `mes`, opcional) | Listar los N últimos/pimeros meses de una subcuenta |

## Reglas de diseño

- Enum de dominio: `TipoSubcuentaB100 { save, health }` en `domain/enums/`.
- Modelo de dominio: `B100Balance` (`id, tipoSubcuenta, mes, balanceMensual, dineroHacienda, dineroTotalRepartir, porcentajeHacienda, pagadoHacienda` + fechas), con `mes` de tipo `String` (`YYYY-MM`).
- Entidad JPA: `B100BalanceMO` (`@Table(name = "b100_balances")`).
- Sin FK a `cuentas`: el tipo de subcuenta es propio de B100, no reutiliza el catálogo genérico.
- Patrón hexagonal del proyecto, como `InteresAnualMintos` o `BalanceFondo`.
